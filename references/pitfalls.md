# 犯过的错和对应的规则

这个 skill 的做法来自 2026 年 10–11 月六张清单的实测（6、39、77、22、22、158 篇；最后那张 158 篇的缺失清单从 11-18 做到 11-21，到手 154 篇：学校渠道和公开版本 146 篇，科研通求助 8 篇）。时间和信任主要丢在这几处，下面各条把它们拆开写：

- 把整张清单丢给 scansci 批量下载，卡到 1800 秒超时，30 分钟只拿到 4/39 篇，还混进一篇被标成 verified 的错文件。
- 并行打开 ScienceDirect，学校出口 IP 被封了十来分钟。
- 事后才统一改名，返工一遍。
- 用 Chrome 扩展逐步操作：单次执行 45 秒上限、一批 90 秒上限、关标签页弄丢标签组、Chrome 一重启扩展就连不上；靠后台任务等文件落地，等超时了就当下完，关掉标签页，杀掉了 6 篇还在取的文章，还收进一个被截断的 0 页文件。
- 在一个库里没找到就归到科研通（POM 的文章 EBSCO 只有题录，其实 Wiley 经 WebVPN 6 秒就能下）。
- 用户在一个浏览器里登了 WebVPN，工具却要用户在另一个窗口再登一次。

现在的分工：`litdl.py` 管清单、核验、入库、记账；`litbrowser.py` 用 Playwright 接管一个专用 Chrome，登录一次，排队逐篇下，自己控制节奏、查截断、写进度文件。

整理日期 2026-11-21（这一天把编号整体重排过，更早的记录里提到的 15a、51c 这类带字母的编号是旧的）。素材是历次下载会话的记录（2026-10-22 一张 6 篇的清单、10-29 一批 22 篇入库、11-06/07 一张 39 篇的经管清单、11-18/19 一张 158 篇的缺失清单、11-20/21 在科研通应助和发求助），加上 2026-11-08 一份错误经验核查报告里归到本 skill 的条目。表里的"用户"是这个 skill 的原作者，引的是用户当时的原话。每条写：发生了什么，依据（用户原话或记录），现在的规则，由谁保证。"脚本"指 `litdl.py` / `litbrowser.py` 已经强制；"我"指要靠执行时自己遵守。

## 一、登录和用户要动手的事

| # | 发生了什么 | 依据 | 规则 | 谁保证 |
|---|---|---|---|---|
| 1 | 用户已在日常 Chrome 登了 WebVPN，工具却让用户在自带窗口再登一次 | 用户："不应该是基于webvpn那个页面去下载吗？"（11-06） | 全流程只登录一次：专用 Chrome 一个会话，浏览器通道和 curl 通道共用。第一次弹窗前说明为什么是单独的窗口 | 脚本（`vpnfetch --from-browser`）加我 |

| 3 | 只说"在我刚打开的标签页里登"，隔了一夜用户得自己要页面 | 用户："打开页面，我来登录"（11-07）；"连上了，你弹出登录的网页"（11-19） | 每次要用户登录或点验证，页面由我打开并放到前台，说明哪个窗口、什么标题。隔了一段时间重新查状态 | 脚本（`login`、`NEED_USER` 时置前）加我 |

| 6 | 用户要求代点人机验证，或者接一个能模拟鼠标的工具来点 | 用户："你直接点一下人机认证就可以了"（11-06）；"把这个项目过人机验证的内容加进去"（11-19，先指 windows-mcp）；"帮我把点一下和滑块的功能集成到这个skill当中"（11-19，参照 drissionpage-ai 的做法） | **11-19 起按其要求接入，但范围收窄**：复选框（Cloudflare/reCAPTCHA/hCaptcha）不需要模型，用 Windows 系统鼠标点；点选类和滑块/拼图类需要视觉模型（默认最多 3 次）。认不出、不是这些类型、或试不过就立刻停下请用户点，页面原样留着。账号、密码、短信验证码仍然一律用户自己来；不装反检测浏览器、不改指纹（见 #7）。Cloudflare 先等最多 8 秒看会不会自己放行，有已知 iframe 才点一次，不过就交给模型/人工，不反复硬撞 | 脚本（`captcha_ai.py` + `osmouse.py` + `wait_human`）加我 |

| 8 | 让用户逐篇手点 14 篇，实际点一次验证就够 | 11-06 | 要用户动手的事攒成一轮；验证过了以后同站点一段时间内直接放行 | 我 |

## 七、工具层面的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `--url /doi/pdf/…` 变成 `C:/Program Files/Git/doi/pdf/…`，页内 fetch 报 Failed to fetch | Git Bash 改写以 `/` 开头的参数（2026-11-19 测脚本时撞上） | 写完整网址；`LITB get` 会认出来并报错 |

| 给 Playwright 的事件传内置方法（如 `list.append`）报 AttributeError | Playwright 要给处理函数挂属性 | 包一层 lambda（脚本已处理） |
| 页面跳转途中读页面报"执行上下文被销毁" | EBSCO、WebVPN 会多次跳转 | 脚本里等一下再读，读不到就重读 |

## 八、换成 Playwright 以后不再存在的坑（备查）

**用户点过验证后文件去了哪**：脚本超时离开以后用户才点的验证，文件由浏览器自己下，落在 `~/.litdl/downloads`（11-19 Cardiff、CityU 两篇就是这样到手的）。每轮 ingest 都把这个目录也当 `--src` 扫一遍。

这些是 Chrome 扩展特有的，现在的流程不走扩展：标签组消失、要留"锚"标签页；JS 返回值被替换成 `[BLOCKED: Cookie/query string data]`；单次执行 45 秒上限、一批 90 秒上限；在 `chrome://newtab` 上等待失败；同一标签页只有第一次自动下载成功；PDF 阅读器的下载按钮弹"另存为"；扩展掉线（"Browser extension is not connected"，Chrome 重启后常见）；用 localStorage 在页面里自建下载队列。
